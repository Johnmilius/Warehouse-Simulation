-- You could create a VIEW
CREATE VIEW product_location_summary AS
SELECT 
    fk_location_id,
    fk_product_id,
    SUM(quantity_total) as quantity,
    SUM(quantity_marked) as quantity_marked,
    SUM(quantity_available) as quantity_available
FROM inventory_units
GROUP BY fk_location_id, fk_product_id;

## Which Approach Makes Sense?

Think about these questions:

**1. Can multiple pallets of the same product be at the same location?**
- Example: Location A has 2 pallets of Caramel Baby, Unit 145435 and Unit 145436?

**2. When you mark inventory, do you mark specific units?**
- "Mark 50 blankets from Unit 145435"
- Or just "Mark 50 blankets from Location A" (system picks which unit)?

**3. When you move pallets, do you move entire units?**
- "Move Unit 145435 from Location A to Location B"
- This is easier if units are tracked separately

---

## My Recommendation: **Approach B**

Create `inventory_units` table because:
- ✓ Matches real-world (each physical pallet has a unit ID)
- ✓ Easier to track marking per pallet
- ✓ Easier to move pallets between locations
- ✓ Better for your picking optimization (know which specific units to pick from)
